# Экспедиция DS · КОЗ №3

Начальное решение для командной работы. Есть общее предварительное разбиение территорий, планировщик выборочного доступа к данным, адаптер бейзлайна организаторов и команда расчёта метрики. Собственное обучение пока представлено шаблоном; подготовка тайлов и сборка эталонной разметки ещё требуют реализации.

Команды и ограничения описаны в `docs/workflow.md`. Начните с команд `plan`, `train` и `predict` без `--execute`: они читают только небольшие конфиги и каталог.

## Структура

```text
configs/                  Общие настройки, шаблон личных путей, будущие разбиения
src/ds_expedition/         Код команды: paths.py и audit.py
scripts/                  Короткие команды запуска из исходников
inference/                Место для будущей конкурсной точки входа
vendor/organizer/         Оригинальный код метрики и примеров организаторов
docs/                     Договорённости о разработке
data/                     Локальные данные и производные — вне Git
models/                   Локальные веса — вне Git
results/                  Локальные результаты — вне Git
materials/                PDF, скриншоты, примеры данных — вне Git
pyproject.toml            Метаданные Python-пакета и команды
```

## Начало работы

Используем Python 3.12 или новее. Минимальный каркас использует стандартную библиотеку.

Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e .
Copy-Item configs/paths.local.example.json configs/paths.local.json
```

На Linux/macOS используйте `.venv/bin/python` и `cp`. Если личный конфиг уже существует, отредактируйте его вместо копирования шаблона.

В `configs/paths.local.json` укажите свою папку с данными:

```json
{
  "dataset_root": "E:/datasets/train-koz-3"
}
```

Этот файл игнорируется Git. На текущем рабочем компьютере он уже создан с существующим путём к Яндекс Диску. Переносить датасет в репозиторий не требуется.

Посмотреть настройки без чтения датасета (установка пакета необязательна):

```powershell
python scripts/show_paths.py
```

После установки пакета доступна команда `ds-paths` при активном виртуальном окружении.

## Правила путей

Приоритет: `configs/paths.json` → `configs/paths.local.json` → переменные окружения → явный аргумент команды, если предусмотрен.

Все относительные пути считаются от корня проекта, независимо от текущего каталога запуска. Используйте `pathlib` и `ds_expedition.paths.load_paths()` в новом коде. Абсолютные пути участников не записываем в общие конфиги.

Переменные окружения:

- `DS_EXPEDITION_DATASET_ROOT`
- `DS_EXPEDITION_MANIFESTS_DIR`
- `DS_EXPEDITION_PREPARED_DATA_DIR`
- `DS_EXPEDITION_MODELS_DIR`
- `DS_EXPEDITION_RESULTS_DIR`

Пример PowerShell: `$env:DS_EXPEDITION_DATASET_ROOT = 'E:/datasets/train-koz-3'`.
Пример Bash: `export DS_EXPEDITION_DATASET_ROOT=/mnt/datasets/train-koz-3`.
Файл `.env` автоматически не загружается.

Корень определяется по расположению пакета при установке `pip install -e .`. При другом размещении пакета задайте `DS_EXPEDITION_PROJECT_ROOT` с путём к checkout, содержащему `configs/paths.json`.

## Инвентаризация — для следующего этапа

Справка, без чтения данных:

```powershell
python scripts/audit_dataset.py --help
```

Когда потребуется запустить инвентаризацию:

```powershell
python scripts/audit_dataset.py
```

Используются пути из конфигурации. Можно передать путь к датасету первым аргументом и `--output-dir` для другой папки результатов. После установки пакета также доступна команда `ds-audit`.

Обычный запуск перечисляет файлы и читает их метаданные. Флаги `--read-utm` и `--count-annotations` дополнительно читают JSON/GeoJSON и могут вызвать скачивание файлов Яндекс Диском. Сводки сохраняются в `data/manifests/` по умолчанию. Это каталогизация, а не проверка геометрии или обучение.

## Что передавать через Git

В Git входят код команды, `pyproject.toml`, общие конфиги, документация и исходные скрипты организаторов. Веса и архивы внутри `vendor` игнорируются. Дополнительные зависимости объявлены в группах `baseline` и `evaluation`; они не входят в минимальное окружение. Версии ещё нужно зафиксировать после первого реального запуска на выбранном оборудовании.

`.gitignore` исключает локальные конфиги, данные, большие GIS-файлы, веса, архивы, результаты, временные файлы и окружения. Маленькие списки территорий для воспроизводимых экспериментов будем сохранять в `configs/splits/`.

Если репозитория ещё нет, создайте его или перенесите структуру в командный репозиторий. Перед первым коммитом:

```powershell
git init
git add --dry-run .
git status --short --ignored
git add .
git diff --cached --stat
git commit -m "Initialize team project structure"
```

Не используйте `git add -f` для данных и весов. `.gitignore` не исключает файлы, уже попавшие в индекс или историю существующего репозитория: такие случаи разбираются отдельно.
